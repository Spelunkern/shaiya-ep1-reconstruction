# Exact workflow for an AI agent

Work from the fork root on a block reserved in upstream/main. Read `AGENTS.md`,
`CONTRIBUTING.md`, and `docs/PROTOCOL.md`. Use English for project-authored content.
Use the existing example only to reproduce its tests, not as an available task.
Windows users have native commands in [WINDOWS.md](WINDOWS.md).

## Verify the task

The contributor supplies a prompt generated by `reverse.py prompt`, containing
block, user, binary path, SHA-256, and baseline. Check the accepted reservation
and its expiry. A reservation in a local branch does not prove central acceptance;
check upstream/main after `git fetch upstream`.

```bash
python tools/reverse.py show BLOCK_ID
python tools/reverse.py verify
python tools/reverse.py audit --originals
python tools/reverse.py start BLOCK_ID --owner GITHUB_USER
```

Use `start` only if the directory does not exist. Binaries are already included;
client data is not needed. Preserve originals and the frozen baseline.

## Prepare Ghidra

Linux x86_64:

```bash
python tools/install_toolchain.py
export GHIDRA_HOME="$PWD/work/toolchain/ghidra_12.1.4_PUBLIC"
export JAVA_HOME="$PWD/work/toolchain/jdk-21.0.12.1+1"
python tools/reverse.py analyze --binary BINARY_ID
python tools/reverse.py export BLOCK_ID
```

On Windows use the installation and environment commands in `WINDOWS.md`.
The installer verifies packages; existing installations of the pinned versions
are supported. `analyze` reproduces the baseline, and `export` checks project
identity and body digest. Preserve diagnostics on failure; do not use stale
outputs as new evidence. Inspect data/classification blocks directly by ranges.

## Required analysis

Examine every body instruction, caller, callee, jump, data reference, import, and
callback. Cite image-base-adjusted addresses for each type, offset, convention,
and algorithm decision. Separate Ghidra's proposed signature from proven ABI.
Resolve parameters, return, cleanup, registers, widths, signedness, alignment,
side effects, and errors. Do not assume original names or silently expand scope
when pseudocode follows control flow outside the body.

## Implement and test

Keep source inside the assigned submission. Use stable binary/RVA symbols and
accepted contracts. Preserve relevant 32-bit arithmetic and access ordering.
Internal source helpers are allowed but are not newly recovered original functions.

Use [FIRST_BLOCK.md](FIRST_BLOCK.md) to understand submission format. Choose an
appropriate harness; do not copy its results or ABI. Compare against original
bytes, instructions, or reproducible observations. Document test-double contracts
and keep doubles out of production source.

Record commands, OS, target, compiler versions, cases, logs, and limitations.
Partial CPU emulation is not whole-executable integration. Apply BSD-3-Clause to
project-authored work and preserve the scope described in `NOTICE.md`.

## Finish

Complete `submission.json`: identity, owner, file lists, ABI, dependency contracts,
and unknowns. Use `draft` while questions or verification remain; otherwise use
`ready`. Do not create a self-review in `reviews/`.

```bash
python tools/reverse.py validate --block BLOCK_ID
```

Run the block's tests and report real results and limits. Create a PR only when
the user authorized that submission. For blockers, finish independent evidence
and name the precise missing dependency or environment.
